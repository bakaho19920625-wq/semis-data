# 0. セクターの状態

- 見出し：`### 0. セクターの状態`
- `sector_health.json` から転記する。再計算しない。
- 分量：6〜10行＋小さな表1つ。言葉は plain_language.md 6節。
- 短縮形（「前日から変わった点」に、この節に関わる変化が無い日）：3行（公式ステージと判定ラベル／危険の目安と底の目安／底の局面）。
  帯の表と分野別は省く。
  判定ラベル・目安のそろい数・底の局面・帯の状態のどれかが変わった日と、火曜の配信（週の最初の日次）は全部書く。
- 1行目（公式。取れる日は必ずこちらを先に書く）：公式ステージ（market-data `stages`。基準日が違えばその旨）。
  SOXX・SMH の細区分と言葉（`label`・`label_ja`、since）、監視：半導体 のステージ分布（`pct_stage`、4週前）とラベル（`label_ja`）。
  「上昇」「下落」の割合として読む人に示す数字は公式だけにする（例「半導体38銘柄の74%が下落（ステージ4）、4週前は8%。業種の調子は弱い」）。
  取れない日は「公式ステージ：取得できず」と書いて2行目だけにする。
- 2行目（機械判定。簡易版）：判定ラベルを言葉で。
  割合の**分母（監視する半導体42銘柄）を必ず書き**、判定の理由を4週前との比較で添える（例「機械判定は悪化中：半導体42銘柄のうち、線の上で上向き 10%、線の下で下向き 15%、50日線の上 14%（30週線とその向きで見た簡易版）。4週前は線の上で上向きが42%だった」）。
  意味は `breadth_meaning` のとおり（初回と、ラベルが変わった日は本文に、それ以外の日は巻末の「読み方」に1行）。
  `label` が null なら「判定できず（履歴不足）」。
  簡易版の割合（`stage2`・`stage4`）を「上昇中」「下落中」と書かない。
  公式の「上昇（ステージ2）」「下落（ステージ4）」と同じ言葉になり、同じ日に 74% と 15% が並んで読み違えるため（数え方が違う：公式は週足の細区分、簡易版は30週線の上下と線の向き）。
  公式と大きく離れている日は「簡易版は30週線の向きも条件にするため、長い上昇の直後の急落では『線の下で下向き』が少なく出る（残りの多くは『線を割ったが線はまだ上向き』の中間）」と1回だけ添える。
- 危険の目安：`risk.count`/3 と成立した条件名、`risk.reading`（過去の発生率）を括弧で。
  前日から変わった日はその旨（1節の `risk_count_change` と重複してよい）。
- 底の目安：`washout.count`/3 と成立した条件、`washout.reading`。
  そろい数は「いま売られ尽くしているか」だけを見るので、反発すると減る。
  **数が減った日・3未満の日は、必ず次の「底の局面」で理由を書き分ける**（まだ売られ尽くしていないのか、売られ尽くした後に反発したのか）。
- 底の局面：`washout.phase` を転記する（言葉は `ja`）。
  `code` が none 以外なら次を1〜2行で：起点（`anchor_date`、SOXX終値 `anchor_close`）から何営業日目か、いまの終値は起点比何%か（`close_vs_anchor_pct`）、二番底の線（`lines.retest_close`＝起点の終値）と底割れの線（`lines.breakdown_close`＝起点の−10%）までの距離、起点以降の最安値（`low_since_anchor`）、3条件の再点灯の日（`relit_dates`）、回復の確認（`recovery_confirmed_date`。なければ「未確認：50日線の上がいま○%、50%超で確認」）。
  続けて過去の経過を1行（`after_all3_reference` と `expected_from_past`）：「過去5回は、3条件が1〜4営業日で外れた後、起点から3〜13営業日後（平均8、中央値9）に二番底（起点の終値から−0.5〜−9.1%）を付け、5回中4回はその日に3条件が再点灯した。今回に当てはめると二番底の時期は○/○〜○/○（平均なら○/○ごろ）、回復の確認は○/○〜○/○ごろ。予測ではなく過去の範囲」。
  この1行は局面が none 以外の間、毎日書く（日付は `expected_from_past` から。米国の休場日は考慮していない旨は初回だけ）。
  局面ごとの書き方：売られ尽くし中＝「3条件がそろっている。過去は1〜4日で反発して外れた」／反発中・二番底待ち＝「売られ尽くした後の反発。過去は5回とも、この後に起点の終値を一度割った」／二番底を試し中＝「起点の終値を下回っている。過去の型の範囲（−9.1%まで）」、再点灯なら「3条件が再びそろった。過去は二番底の日に再点灯するのが通例で、底割れではない」／底割れ＝「起点の−10%を割った。過去5回のどれよりも深い（2022年6月型＝悪材料が続いた局面に近い）」／回復を確認＝「50日線の上が半分を超えた。過去はここから高値回復まで進んだが、2022年6月はその後に安値を更新した」。
  none（直近60営業日に3条件そろいなし）の日は「売られ尽くしはまだ起きていない。1〜2条件は底探しの入口（だまし約4割）」と書く。
  `dates_all3_in_history` の直近の日付を1つ添える。
- 相対力の帯（表1つ）：行＝短期（EMA21）・中期（EMA50）、列＝市場・テック全体・ソフト・ハード（緑／赤と EMAとの差%）、右端に 緑の数、そろってからの日数（`all_red_days`／`all_green_days`）、状態（`state`、`state_since`）。
  `benches_missing` があれば「未取得：○○（次回の自動更新で入る）」。
  帯は描写であり、乗り換えの合図ではない（15年で乗り換えは持ちっぱなしに負けた）と、状態が変わった日だけ1行添える。
- 分野別：`subsectors` の net_2_minus_4 と above50 を1行で（例「分野別では光・後工程と製造装置が最も弱く（net −50／−20）、設計ソフトだけ底固め（+50）」）。
- `sector_health.json` が無い（旧データ）または status が ok でない日は「セクターの状態：未取得（理由）」の1行だけ。
