# 半導体・メモリー定点観測｜判定基準（v6.9 の採点定義。変えていない）
# prompts/judge.md の進め方 5（採点）と 6（反転リスク・シナリオ・予測）で読む。節ごとの書き方は prompts/judge/ のほかのファイル。

## 1. 採点の手順
1. 各小項目を−2～+2の5段階で判定。
   3節の表は+2・0・−2の基準で、+1・−1はその中間。
2. 点数＝配点×（段階＋2）÷4。
   全項目0なら50点。
3. 欠損：材料がない小項目は前回の段階を据え置き、連続回数を付ける（`0*1`）。
   2回連続で据え置いたら3回目は0へ1段階戻す。
   前回もなければ除外し残りの配点で100点換算。
   据え置き＋除外がサブスコア配点の30%を超えたら、そのサブスコアの確信度上限はB。
4. 段階を変えた小項目は「ID 前回→今回 理由」を1行で残す（SCORES.drivers）。
5. 同じ事実を複数の小項目で満額加点しない（R11）。

## 2. スコアの構造
- サブスコア（0～100）：A（AIインフラ需要）、M（メモリーサイクル）、F（ファウンドリー・装置・先端パッケージ）、E（業績改定・バリュエーション）、X（マクロ・規制・地政学）、S（SOXモメンタム）、D（メモリー株モメンタム）。
  TECHNICAL＝0.7S＋0.3D（levels.json が計算済み）
- 総合点＝0.20A＋0.25M＋0.20F＋0.10E＋0.10TECHNICAL＋0.15X。
  内訳は配点換算で表示（AI＝A×0.20「/20」）
- ラベル：75～100強気、60～74やや強気、45～59中立、30～44慎重、0～29弱気。
  半導体ビュー＝総合点、メモリービュー＝M。
  MとDが20点以上離れたら「価格との不一致」と注記
- THESIS_INVALIDATION が発動したら総合点より優先してラベルを1段階以上下げる
- 総合点は±5の帯を付けて書く。
  「スコア変化」と呼ぶのは総合点が5点以上動いたか drivers に載る段階変更があるときだけ
- **モメンタムは現状の描写で予測ではない。**
  過去3年のSOXXではS1が−2の後の60営業日リターン中央値が全段階で最高だった。
  SとDで0～3か月のシナリオ確率を±5ptより大きく動かさない

## 4. 領域ルール（R）
- **R1 製品別に判定する。**
  DRAMはHBM／server・DDR5／mobile LPDDR／legacy（DDR4、LPDDR4/4X、specialty）、NANDはSLC/MLC／TLC／QLC／PLC／HBF・SCM／client・mobile／eSSD／HDD代替を分ける。
  「DRAM強気」「NAND弱気」だけで終わらない。
  PLCは量産・採算の確認前は基本ケース外。
  HDD代替とHBM/DRAM補完は重なり得るため根拠のない比率配分をしない
- **R2 DDR4スポットはlegacy全体の方向感にだけ使い、LPDDR4X等の契約価格・供給の代わりにしない。**
  特殊需要（車載・産業・ネットワーク・モデム）は搭載容量×出荷台数×採用率で確認できる場合だけ基本シナリオに入れる
- **R3 実効bit供給＝wafer投入×die/wafer×歩留まり×bit/die×稼働率×製品mix×認定・量産時期。**
  層数の上昇や見出しだけで供給増と判定しない
- **R4 光/CPOは単独ではHBM弱気にしない。**
  外部メモリー階層の本番採用に加え、主要GPU/ASICの1台当たりHBM搭載量または発注見通しの下方修正が確認された場合だけ弱気材料を強める
- **R5 HBM需要は、1台当たり容量・帯域・台数・稼働率・総ジョブ数・業界総HBMビットを分ける。**
  1ジョブ当たりの削減だけで総需要減としない
- **R6 SRAM増加はファウンドリー・ロジック需要であり、メモリーメーカー売上に直接加えない。**
  オンダイ容量、ダイ面積、歩留まり、外部メモリー必要量、対象ワークロードを確認する
- **R7 AI効率化（量子化・蒸留・MoE・KV圧縮・EGGROLL等）は、比較対象、モデル規模、学習/推論、独立再現、本番採用で評価し、総メモリービット需要の下方修正が確認されるまで弱気材料にしない**
- **R8 導入段階：0構想、1標準化、2試作/サンプル、3顧客認定、4量産、5重要売上。**
  段階3以下は技術シグナルで、業績シナリオへの加点を制限。
  標準発表や単一実験で業績予想を上方修正しない
- **R9 分解・リークの証拠：A＝メーカー資料・刻印・複数独立分解、B＝信頼できる単一分解・限定開示、C＝ダイ面積推定・専門報道、D＝リーク・SNS。**
  ダイ面積だけで世代・容量・メーカーを断定しない。
  端末メインメモリーとモデム等のパッケージ内DRAMを混同しない。
  単一端末から業界需要を外挿しない。
  未発表ロードマップは「リーク/市場予想」と表示
- **R10 CXMT/YMTCは公式と専門調査を分け、非開示のwafer能力・歩留まり・顧客を断定しない**
- **R11 二重計上の防止。**
  ファンダはM、株価・フローはDで採点。
  DRAM ETFの上昇を需要改善とテクニカル改善で二重加点しない。
  実質金利はX1のみ。
  DRAM上位銘柄と個別株を同じ要因で重複加点しない。
  SOXX・SMH・DRAMの共通保有による見かけの広がりに注意。
  HBF需要をHBM減少とNAND増加の両方へ自動反映しない。
  ADRプレミアム・NAV乖離・スプレッドは業績の加点でなく価格形成の信頼性の調整に使う
- **R12 CAPEXの質。**
  良い＝HBM・先端パッケージ・eSSD・HBF/SCM等の高付加価値mix、顧客認定・長期契約・前払い・供給コミット、ボトルネック解消、需要＞実効供給。
  中立＝維持更新・技術移行・地域分散で数量コミット不明。
  悪い＝顧客コミットのないcommodity bit増、wafer・歩留まり・bit densityの同時上昇、在庫増、稼働率低下、契約価格下落、HBMプレミアム縮小、commodityへの逆流
- **R13 ADR・上場市場。**
  SKHY理論値＝韓国普通株×0.1÷USD/KRW（`adr_premium.csv`、約14.5時間の時差を含む近似）。
  プレミアム拡大を業績改善として加点しない。
  縮小は企業価値が同じでも株価下落要因になるため独立リスクとする。
  米国上場を米国企業化や韓国市場・ウォン・ガバナンスリスクの消滅と解釈しない。
  DRAM ETFも原資産・通貨・swapのリスクが残る。
  投資手段比較は純度・事業mix・上場市場・通貨・価格形成・重複を比べ、個人向け配分は示さない
- **R14 DRAM ETF。**
  運用期間が短い間はSMA200・52週・長期ベータN/A。
  設定前データを合成せず他ETFで補わない。
  保有銘柄の基準日が古ければ構成分析は参考。
  純流入は確認元不明なら表示しない。
  NAV乖離・スプレッド急拡大時はテクニカル信頼度を下げる。
  アクティブ運用・swap・T-Billで構成銘柄の単純加重と差が出ることを明記
- **R15 稼働タイミング。**
  「AI投資が続くこと」と「個別企業が予定どおり売上を立てること」を分ける。
  計画容量（GW/MW）・変電所の通電・DC本体の完成・GPU設置・顧客への引き渡し・課金開始は別の段階で、計画容量や「確保した」という数字だけで A4 を加点しない。
  受電・引き渡し・課金開始の3つの日付は一致しないので、会社が示す「稼働予定」がどの日付かを確かめる。
  新規供給の遅れは、既存設備を貸す側（稼働済みDC・ネオクラウドの既存容量・DC向けREIT）には追い風、新しい機器を売る側（GPU・メモリー・光部品・電源冷却）には出荷鈍化の材料で、方向が逆になる。
  本レポートの採点対象は売る側なので、GPUレンタル価格の上昇を A2・M2 の加点にしない（貸す側の追い風は 6a節に事実として書くだけ）。
  「米国のDC計画の何割がリスク」のような数字は、計画段階か建設中か、いつの稼働予定かを分けるまで売上減少率に置き換えない。
  「他州・海外へ移せる」は長期の緩衝材であり、同じ時期・同じ費用で稼働できることの証拠にはならない。
  CapEx 総額が同じでも内訳（建物・電力設備 vs 機器）と支出時期が変われば半導体の売上時期は変わるので、A1 は総額、A4・A5 は時期として別に見る

## 5. 反転リスク（未発動・警戒・発動）
AI CapEx鈍化・AI収益化失望／製品別価格の悪化／在庫増・稼働率低下・commodity bit供給増／TSMC月次・先端ノード・装置受注の悪化／金利・VIX急騰、対中規制、台湾・地政学／電力・冷却・パッケージ・ネットワーク制約／AI効率化による総ビット需要の実際の下方修正／光・CXL・HBF・SRAM採用と同時のHBM搭載量・発注下方修正／DRAM ETFの相対強度低下・下落日出来高増・流動性悪化／SKHYプレミアム急縮小、韓国市場・ウォン急変／テック内部の崩れ・ブレイクが伸びない地合い（market-data。略称「テック内部の崩れ」）／米国内のDC規制・許認可／AI投資の資金調達・信用

「テック内部の崩れ」は機械的に状態を決める（P。market-data の値を転記して判定し、裁量で変えない）：
- 発動：テック内部のラベルが broad_decline、かつ IX3（指数の崩れガード）が成立
- 警戒：上に当たらず、次のいずれか：テック内部のラベルが stealth または broad_decline／IX3が成立／FB1_stalling が真
- 未発動：どれにも当たらない
発動・警戒でも THESIS_INVALIDATION を自動で発動させない。
0～3か月のシナリオ確率を動かす場合は、判定基準2節の「SとDで±5ptより大きく動かさない」と合わせた上限として扱い（テック内部の分を上乗せしない）、理由に書く。

「米国内のDC規制・許認可」の目安（証拠YAMLの DC_TIMING.regulation と projects から。公約・報道だけでは段階を上げない）：
- 未発動：新規DCの停止措置が1州（テキサス）以内で、再開の条件（監査完了等）が公表されており、追跡案件の引き渡し延期が決算で確認されていない

  「電力・冷却・パッケージ・ネットワーク制約」は物理的な供給の項目で、同じ事実を両方で発動させない。
  対中規制（X3）とも別

「AI投資の資金調達・信用」の目安（DC_TIMING.financing、CAPEX、EARNINGS から。10/30 に「AI CapEx鈍化・収益化失望」の内訳としていた資金調達・信用の監視指標（Amazon FCF、MSFT の第三者DCの遅れ、ネオクラウド株）はこちらへ移し、二重に数えない）：

- 注：HY スプレッドの水準はプライベートクレジット監視レポートと同じ出典・同じ目安を使う（数値はこちらに書き写すだけ）。

## 6. シナリオ確率
0～3か月、3～12か月、1～3年ごとに強気・基本・弱気を5%刻み合計100%。
各シナリオに前提、先行指標、確率、SOXの方向、製品別メモリー価格・利益、DRAM ETF・個別株の方向、無効化条件。
確率変更は前回からの幅と理由を書く。

## 7. 予測の書き方と検証
- 毎回3～6本（0～3か月中心、3～12か月を1～2本）。
  id（F2026-10-25-1）、horizon、statement、metric_source、condition（数値条件）、deadline、probability（5%刻み）を付け、`forecasts.csv` に1行追加。
  期限と数値条件だけで白黒がつく形にする
- 判定は二値：hit／miss／void（データ未公表。分母に入れない）。
  「一部的中」は使わず、方向だけ合ってもmiss。
  期限前に確定すれば早期判定可。
  未確定はopenのまま
- missの理由はデータ不足・重み付け・想定外イベント・タイムラグのいずれかを明示し、修正点を書く。
  Brier＝（probability÷100−結果）²、hit=1・miss=0。
  TRACK_RECORDは累積

## 8. 証拠の確信度
A＝複数の一次情報・数値整合・独立確認／B＝一次情報はあるが範囲限定／C＝専門二次情報中心・非開示多い／D＝推測・リーク・単一報道・再現前の研究。
プレプリント、標準発表、単一企業コメント、短期ETF価格、単一分解だけでAにしない。
